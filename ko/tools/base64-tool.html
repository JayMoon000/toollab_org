표준 Base64 vs URL-Safe 규격(RFC 4648) 비교

Base64는 64개의 안전한 ASCII 문자를 사용하지만, 웹 전송 환경에 따라 특수문자 충돌을 방지하는 대체 규격이 적용됩니다.

인코딩 표준 62번째 문자 63번째 문자 패딩(Padding) 주요 용도 및 활용처
RFC 4648 (표준 Base64) + / = 이메일 첨부(MIME), XML 데이터, CSS 인라인 Data URI
RFC 4648 §5 (URL-Safe) - _ 생략 또는 제거 JWT 인증 토큰, URL 쿼리스트링, 웹 슬러그 전송

웹 개발에서의 Base64 활용 원리

1. HTTP 요청을 줄이는 Data URI

작은 아이콘이나 파비콘을 CSS 파일이나 HTML 문서에 Base64 Data URI 형태로 직접 인라인 삽입하면 브라우저의 추가적인 네트워크 요청 횟수와 레이턴시를 크게 절감할 수 있습니다.

2. 한글 UTF-8 멀티바이트 안전 보장

브라우저 기본 btoa() 함수는 1바이트 라틴 문자만 지원하므로 한글 변환 시 예외가 발생합니다. 본 도구는 TextEncoder와 바이트 정규화 처리를 통해 한글 음절을 글자 깨짐 없이 완벽히 변환합니다.

자주 묻는 질문 (FAQ)

Q. Base64로 변환하면 암호화(보안)가 되는 것인가요?

아닙니다. Base64는 이진 데이터를 텍스트 전송 환경에서 안전하게 전달하기 위한 '인코딩(규격 변환)' 포맷일 뿐이며, 누구나 원문으로 복원할 수 있으므로 비밀번호나 중요 데이터를 숨기는 암호화 용도로 사용해서는 안 됩니다.

Q. 인코딩 후 파일 용량이 약 33% 늘어나는 이유는 무엇인가요?

Base64는 원본 데이터의 3바이트(24비트)를 6비트씩 4개로 쪼개어 표현하기 때문에, 필연적으로 데이터의 물리적 크기가 약 33% 증가(4/3 배율)하게 됩니다.
